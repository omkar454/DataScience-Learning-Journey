3) Docker command to run the image and then resulting in creation of container-:
```
docker run -d -p 80:80 docker/getting-started
```
### 🔹 Meaning

#### 1. `docker run`

* Creates and starts a new container from an image
* Main command used to run containers in **Docker**

---

#### 2. `-d` (Detached Mode)

* Runs the container in the background
* Terminal remains free for other commands

---

#### 3. `-p 80:80` (Port Mapping)

* Maps ports between host and container
* Format: `host_port : container_port`
* Here:

  * `80` (host) → `80` (container)
* Access via: `http://localhost`

So; we are accessing the application which is at port: 80 within the container via port: 80 of local host(our local device) via port mapping functionality of "docker run" command
---

#### 4. `docker/getting-started` (Image Name)

* Name of the Docker image used to create container
* If not available locally, Docker pulls it from **Docker Hub** and then installs it in your local server and then runs the pulled image.

First; we need to pull & download the image in local server and then only it can run in our local server.
* DOCKER RUN command can do both pulling image from DOCER-HUB and then running the image resulting in creation of a container if the image is NOT available in our LOCAL-SERVER .
* If the IMAGE is PRESENT in our LOCAL-SERVER then "DOCKER RUN" COMMAND will just RUN THE IMAGE locally present in our DEVICE resulting in CREATION OF CONTAINER.

## 📝 Reason for Port Mapping (Docker) in `docker run` Command

### 🔹 Main Reason
* Containers are **isolated (separate environments)**
* Applications inside them are **not directly accessible**
* To access these applications, we **map a port of the local system (host)** to the **port used by the application inside the container**

👉 This allows us to access the container’s application through `localhost`

---

### 🔹 Why Port Mapping is Needed

#### 1. Access Application

* To open container apps in browser (`localhost`)

#### 2. Enable Communication

* Allows your system to **talk to the container**

#### 3. Testing & Development

* Developers can test apps running inside containers

#### 4. Multiple Containers

* Helps run multiple apps using different ports

---

### 🔹 Example (Multiple Port Mapping for Clarity)

```bash
docker run -d -p 3000:80 -p 5000:80 nginx
```

* `localhost:3000` → container port 80
* `localhost:5000` → container port 80
  👉 Same container app accessed using different ports

---

### 🔹 Why Container Port Cannot Be Changed ❌

* Defined by the **application inside container**
* Docker only maps ports, it **does not change internal ports**
* To change it → need to modify app or rebuild image

---

### 🔹 Key Points

* ✅ Host port can be changed
* ❌ Container port cannot be changed directly
* One container port can map to multiple host ports
* You can easily check the container port by looking at the documentation of that container/image in the dockerHub. The dockerHub clearly shows the container port of that paricular container/image.

---

### 🔹 One Line Summary

👉 Port mapping is needed to **access and communicate with applications inside Docker containers**, while the **container port remains fixed by the application and the container within which it is running.**

## 📝 Important Note (Port Usage in Docker)

### 🔹 Statement

👉 We cannot run multiple containers on the same host port

---

### 🔹 Explanation

* A **host port can be used by only one container at a time**
* If another container tries to use the same port → it will give an **error**

---

### 🔹 Example

❌ Not Allowed:

```bash
docker run -p 3000:80 nginx
docker run -p 3000:80 apache
```

✔️ Allowed:

```bash
docker run -p 3000:80 nginx
docker run -p 4000:80 apache
```

---

### 🔹 One Line Summary

👉 Each container must use a **unique host port** to run simultaneously

7) DOCKER COMMAND TO DELETE AN IMAGE-:

## 📝 `docker image rm` Command & Error (Combined Notes)

---

### 🔹 Command

```
docker image rm image_id/image_name
```

---

### 🔹 Meaning

👉 Deletes a Docker image using its **image ID** or **image_name**

---

## ❌ Error Message

```
PS C:\Users\Omkar Raut> docker image rm d79336f4812b                                                           
Error response from daemon: conflict: unable to delete d79336f4812b (must be forced) - image is being used by stopped container f8527cea4737
```

---

### 🔹 Why This Error Occurred

* The image is **linked to a container**
* The container is **stopped but still exists**
* Docker does **not allow deleting images** used by any container whetejr it is STOPPED or RUNNING -: It does NOT matter.

---

### 🔹 Reason for This Restriction

* A container is **created from an image**
* It still **depends on that image**
* Deleting the image would **break the container**

---

### 🔹 Simple Understanding

* Image = **Template**
* Container = **Instance of that template**
  👉 Deleting template while instance exists → causes problem

---

## 🔹 How to Fix

### ✅ Option 1: Remove container first

```bash
docker rm f8527cea4737
docker image rm <image_id>
```

---

### ✅ Option 2: Force delete

```bash
docker image rm -f <image_id>
```

---

### 🔹 One Line Summary

👉 Image cannot be deleted because it is **still used by a container**, and Docker prevents this to **avoid breaking dependencies**

## 📝 Is Force Delete Possible with Running Container?

### 🔹 Answer

❌ **No, it is NOT possible**

---

### 🔹 Reason

* Docker **does not allow deleting an image** if a container is **running using it**
* Even with `-f` (force), it will **fail**

---

### 🔹 What You Must Do

1. Stop the container
2. Remove the container
3. Then delete the image

---

### 🔹 One Line Summary

👉 You **cannot force delete an image** while a container is actively running on it.
       You can do force deleting of an image only if NO containers are running from that image.

## 📝 Tags in Docker Images (With Proper Usage Examples)

### 🔹 What are Tags?

👉 Tags are **labels given to Docker images** to identify different versions

---

### 🔹 Purpose

* Helps to **differentiate versions** of the same image
* Makes it easy to **use a specific version**

---

### 🔹 Format

```bash
<image_name>:<tag>
```

---

### 🔹 Examples with Docker Commands

#### 1. Using Default Tag (`latest`)

```bash
docker run nginx
```

➡️ Automatically uses:

```bash
docker run nginx:latest
```

---

#### 2. Using Specific Version

```bash
docker run nginx:1.25
```

👉 Runs a specific version instead of latest. 
       1.25 → specific version of image "nginx"
    

---

#### 3. Pulling Specific Version

```bash
docker pull nginx:1.25
```

---

#### 4. Building Image with Tag

```bash
docker build -t myapp:1.0 .
```

👉 Creates image with version `1.0`

---

### 🔹 Important Point ⚠️

* If **no tag is given**, Docker uses **`latest` by default**

---

### 🔹 Why Tags are Important

1. Version control
2. Easy updates/rollbacks
3. Avoid confusion between versions

---

### 🔹 One Line Summary

👉 Tags represent **different versions of a Docker image**, and are used in Docker commands to **run, pull, and manage specific versions**. 
* Tags can eithe be a numeric-: 1.25, 3.4, 8 etc, or can be alphabetic like -: trixie, 8-trixie, alpha etc.
ex-:
* docker pull redis:8.2.5-bookworm ; docker pull redis:8
* here '8' and '8.2.5-bookworm' are different versions/tags of the same "redis" image in DOCKERHUB.

## 📝 Port Rule in Docker (Important Note)

### 🔹 Statement

👉 Container ports can be the same, but host ports must be unique

---

### 🔹 Explanation

* Multiple containers can run applications on the **same container port** (e.g., 80)
* Each container has its own **isolated environment**
* Containers **share the same OS kernel** but run separately
* So, every container gets its own **independent set of ports internally**

👉 But on the host system:

* A port can be used by **only one container at a time**
* Hence, **host ports must be unique**

---

### 🔹 Example

✔️ Allowed:

```bash
docker run -p 3000:80 nginx
docker run -p 4000:80 nginx
```

* Both containers use port `80` internally
* Access via:

  * `localhost:3000`
  * `localhost:4000`

---

❌ Not Allowed:

```bash
docker run -p 3000:80 nginx
docker run -p 3000:80 apache
```

* Same host port → conflict/error

---

### 🔹 One Line Summary

👉 Containers can use the same internal ports due to isolation, but **host ports must be unique to avoid conflicts**
